# Один кадр

Приложение для одного праздника: камера, имя и пожелание, серверный таймер и общая галерея.
Next.js App Router + TypeScript, sharp, React Photo Album и Yet Another React Lightbox.
Без базы данных. Все записи и таймер сохраняются на диске.

## Запуск

Нужен Node.js 22.13+ и npm.

```powershell
npm.cmd ci
Copy-Item .env.example .env.local
```

В `.env.local` при желании задайте `EVENT_NAME`.
Для постоянного хранилища можно задать абсолютный `DATA_DIR`; по умолчанию используется `data` в корне проекта.
Админка и управляющие API доступны без пароля.

```powershell
npm.cmd run build
npm.cmd start
```

Откройте `http://localhost:3000`, для управления — `http://localhost:3000/odmen`.
Для разработки: `npm.cmd run dev`. В Linux используйте `npm` вместо `npm.cmd`.

## Праздник и размещение

1. Запустите один процесс приложения на VPS за HTTPS reverse proxy, например nginx или Caddy.
2. Укажите постоянный каталог `DATA_DIR`, доступный процессу для чтения и записи.
   Не помещайте его внутрь `.next`; сохраняйте каталог при обновлении приложения.
   При Docker-размещении подключите его как volume. Serverless с временным диском не подходит.
3. Разрешите в reverse proxy входящий запрос не меньше 6 МБ: файл до 5 МБ плюс multipart-поля.
4. Создайте QR-код с публичным HTTPS-адресом главной страницы и разместите его на столах.
   Итоговый домен не задан, поэтому готового печатного QR-кода в репозитории нет.
5. Откройте `/odmen`, задайте часы и минуты и нажмите «Старт».
6. Проверьте камеру и отправку на телефонах до начала праздника.

Камера работает на HTTPS либо на localhost. Обычный HTTP по локальному IP телефона не подходит.
Несколько процессов/реплик с общим каталогом не поддерживаются: по ТЗ приложение работает одним процессом.

## Поведение

Гости видят ожидание, форму либо галерею. Статус обновляется каждые 5 секунд и при возвращении во вкладку.
Видимый отсчёт обновляется ежесекундно относительно времени сервера, часы телефона не определяют состояние.
После снимка пересъёмки нет. До отправки фото и текст живут только в памяти страницы.
После успешной отправки в localStorage записывается `partyPhoto` со значением `done`.
При отключённом localStorage подтверждение работает до закрытия страницы, отметка не сохраняется.

Сброс возвращает ожидание, закрывает приём и скрывает список, сохраняя фотографии и отметки гостей.
Повторный запуск использует те же записи. Для очистки после репетиции вручную удалите только папки записей
из своего каталога данных и отметку `partyPhoto` в тестовом браузере.

Данные:

```text
data/
  timer.json
  <uuid>/
    photo.jpg
    photo-min.jpg
    info.json
```

`timer.json` содержит `endsAt` (UTC ISO 8601 или null); `info.json` — только `name` и `text`.
Изображения доступны по `/api/photos/<uuid>/full` и `/api/photos/<uuid>/min`.
JSON и каталог данных не публикуются как статика. Прямые URL фото доступны до открытия галереи согласно ТЗ.

## Проверки

```powershell
npm.cmd run build
npm.cmd run check
npm.cmd test
```

Тест требует готовой сборки, запускает production-сервер на порту 3197 и использует отдельный каталог
`.test-data/run-*`. Он проверяет API, обработку фото, доступ к админке, 30 записей, перезапуск и сброс.
Тестовые каталоги остаются для осмотра; рабочий `data` не затрагивается.
Результаты и ограничения проверки перечислены в [docs/verification.md](docs/verification.md).

Пример подключения библиотек соответствует [примеру React Photo Album](https://react-photo-album.com/examples/lightbox).
API реализовано через [Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers).
